# タスク分析

**task-analyst エージェント**を起動して、渡されたタスク・Issue・バグ報告を実装可能な単位に分解します。
分類・抽出・分解・承認待ちの手順はすべて **エージェント本体が単一の正**(このコマンドは薄い起動器。ADR-014 / 監査 P5)。

## いつ使うか

- サポートモードの起点として(タスク → PR)
- GitHub Issue・バグ報告・改善依頼を受けたとき
- 入力が**具体的なタスク/Issue**なら `/analyze-task`、**曖昧な要望/新機能アイデア**なら `/requirements`

## 次のステップ

`/autorun` の analyze-task フェーズとして起動された場合は、承認後 `plan`→`tdd` へ同一 RUN_STATE
のまま自動的に継続する(手動でコマンドを挟む必要はない)。

このコマンドを単体で明示的に呼んだ場合は、承認後に `/plan`(実装計画)へ進む。**そのあとの実装を
裸の「実装して」で呼び直さないこと**——スコープ・受け入れ基準が引き継がれず、判定がやり直しになる。
続けて実装するときは `/autorun` に渡してこの内容を support モードの起点として採用させる。
